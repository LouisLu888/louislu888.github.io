Replit 实验：32 个 agent 提速 18.9 倍，有的模型超过 8 个反而变差

Replit 的研究显示，同样两小时，Opus 5.5 优化 NumPy 时单 agent 提速 3.7 倍，32 个 agent 提速 18.9 倍；GPT-6.2 Astra 单打最强，超过 8 个 agent 后反而变差。

谁说的
Replit CEO Amjad Masad 在 X 上发布公司关于 agent 集群扩展规律的研究，并开源了 Optimization-Bench。
核心观点
他们的结论是：增加 agent 数量可以大幅提升效果，但算力加多了不一定更好，agent 怎么组织起来同样关键。
依据
实验在固定两小时内完成。模型会自发形成不同的组织结构，去中心化的集群比依赖中心调度的扩展得更好。问题本身能不能拆开并行做，最能预测集群的表现。单个模型越聪明，不代表集群越强。
对你的意义
给团队上多 agent 并行之前，先看任务能不能拆开并行做。可以分别用 1、4、8 个 agent 跑同一个任务，比较结果再决定规模。
争议·条件
实验做的是性能优化这类结果可以量化的任务。写方案、做设计这种难以评分、步骤环环相扣的工作，不一定适用同样的规律。

Amjad Masad 在帖子里公布了 Replit 的一项研究：同样给两小时，用 Opus 5.5 优化 NumPy，单 agent 提速 3.7 倍，32 个 agent 提速 18.9 倍。GPT-6.2 Astra 单独跑是最强的，但超过 8 个 agent 后出现负扩展。

对正在给团队铺 coding agent 的人，有两点可以直接用。第一，先判断任务能不能拆开并行，这是最强的预测指标，加人头或加 agent 都要先过这一关。第二，单兵最强的模型不一定适合组队，选模型要在你实际的并行规模下测。研究还发现，让 agent 自己分头推进的集群，比一个总指挥分派任务的集群扩展得更好。他们开源了 Optimization-Bench，可以拿来复现。
