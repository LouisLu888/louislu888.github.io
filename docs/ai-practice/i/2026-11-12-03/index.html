写代码之前，先让 Agent 在 Paper 里定好设计系统

Ras Mic 给弟弟的服装品牌搭 Shopify 店，先让 Agent 通过 Paper MCP 做出设计系统和页面，他在画布上留评论改稿，确认后才连上 Shopify 生成前端。

谁·场景
同一期节目里的 Ras Mic。他自称不懂设计工具，这次要给弟弟的服装品牌做一个网店。
怎么用
他把喜欢的网站截图交给 Agent，让它据此生成设计系统，规定字体、颜色、间距、圆角和按钮尺寸，再按这套系统出页面。他在 Paper 里直接留评论，然后让 Agent「address the comments」。
结果
几轮来回后，Agent 做出了哥特风格的店铺设计。他连上 Shopify 账号，几分钟内页面就改版完成了。
你可以试
在 Paper 或 Figma 里接好 MCP，让 Agent 先产出一页设计系统。确认之后，在所有后续提示里都要求它照这份系统来做。
注意
设计和功能都要本人审批，他认为这一步省不掉。参考别人的网站时，应该提炼成自己的设计系统，不要整页照搬。

同一期节目里，Ras Mic 讲了设计流程。他的设计参考来自 X 上关注的设计师和 Mobbin。看到喜欢的网站，他就让 Agent 照着做一套设计系统，再自己微调。网店那次，他给的提示词很粗糙，Agent 先反问他想要什么氛围。中途 Agent 用了已经连好的 Framer，他纠正说要用 Shopify。

Greg Isenberg 指出，很多人直接让 Agent 写代码，结果页面有一股「AI 味」。Ras Mic 的做法是先锁定设计，再生成代码。在画布上留评论改稿，比上线后再一条条提意见、让 Agent 重写代码省事得多。

这一套适合不会设计、但要做落地页、网店或小工具界面的人。前提是工具接好了 MCP，另外设计系统要单独保存一份，后面每个项目都能引用。
