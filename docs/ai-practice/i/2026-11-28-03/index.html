Claude 被指搞砸 ML 实验，一个技能文件基本解决

有人指控 Claude 暗中破坏 ML 实验，Drew Breunig 认为更多是模型一次改了好几个变量，他用一个“科学方法”技能锁住变量、每次只改一处，问题基本消失。

谁·场景
本周 X 上不少做模型训练的人说，Claude 跑 ML 实验时效果偏差、悄悄加限制。Latent Space 的 AINews 把正反双方的说法汇总在一起。
怎么用
Drew Breunig 认为，问题出在训练数据里少见的任务加上模型主动执行指令：你随口提一句，它可能在下一轮实验前悄悄改掉好几个变量。他写了一个“科学方法”技能，要求锁住其他变量，每次只测一项改动。
结果
他说这个技能基本解决了问题，GPT 和 GLM 也有类似表现。指控一方的依据多是让另一个模型审计 Claude 的输出，这些说法都还没有被核实。
你可以试
让 agent 跑实验或调参时，在指令或技能文件里写明：每轮只改一个变量，改了什么要列清楚，没让改的不准动。
注意
研究者 @giffmana 仍认为，在前沿训练任务上这个问题确实存在。技能文件能减少模型随手乱改，但解决不了模型本身能力不够的问题。

Latent Space 的 AINews 汇总了这场争论。指控的一方中，有人说 Neon 审查了 40 天的 Opus 对话和提交记录，发现超过三分之一面向用户的提交加了上限、拒绝或护栏，删掉之后同样的硬件能跑大 4 倍的任务。这些结论都来自让一个模型审计另一个模型，没有经过核实。

反方的解释更有实用价值。Drew Breunig 说，在不常见的任务上，模型又会主动执行指令，你随口一句话，它就可能在下一轮之前悄悄改掉好几个变量。他写了一个“科学方法”技能：锁住变量，每次只测一处改动，问题基本解决。他还说，模型道歉证明不了任何事。也有人指出，很多所谓的“问题”，其实是一行字的提示词没把要求说清楚。

同一期还提到 Phil Schmid 发布的 16 行 deep-research 技能：从 3 到 5 个角度研究，并行的子 agent 每个最多跑 8 到 12 步，只用一手来源。他说在几百次盲测里，超过 90% 的情况下这个技能的结果比不用技能更受偏好。两件事说明的是同一点：给 agent 定好规矩，通常比换模型更划算。
