01｜一个人卖 84 款数字产品，月收入 8 千到 1 万美元

谁·场景
新加坡的 Anfernee Tan，管理公司时累到倦怠，2023 年 8 月辞去总监职务，转做一人生意。
怎么用
从自己熟悉的 Notion 模板做起，用免费产品收集订阅者，再用 3 天到 45 封不等的自动邮件序列推付费产品；AI 是他的产品主题之一，也用在自动化上。
结果
他说月收入 8000 到 10000 美元（收入，非利润）：Gumroad 约 70%，Substack 付费订阅约 10%，新加坡线下培训 10% 到 20%；Gumroad 订阅者约 3 万到 4 万，AI Toolbox 卖出 3000 多份。
你可以试
把自己天天在用的一套工具或模板整理成一个免费下载，配一组 3 到 5 封的跟进邮件，看有多少人下载、多少人回信。
注意
Gumroad 的邮件自动化功能简单，同一个人下载多个免费品会同时收到多组序列，已经有订阅者抱怨邮件太多，系统越大越难整理。

Anfernee Tan 在 Niche Pursuits 节目里讲了他的一人生意。起点是他本来就在用的 Notion。早期他大约每周上架一款新产品测需求，店里最多时有 84 款，价格从免费、5 美元、9.9 美元，到 77、97 美元和 100 美元的套装。他原本没抱太大期望的 AI Toolbox，后来卖了 3000 多份，属于中等价位。

收入主要来自免费品 → 订阅 → 长周期邮件序列这条链路。下载不同免费品的人进入不同序列，短的 3 天、5 天，长的 20 封、45 封，跟进期六到九个月。他的逻辑是，今天下载的人未必今天就需要付费产品，几周后熟悉了他，才可能买。

代价也出现了：Gumroad 没法在一个人进入新序列时把他移出旧序列，邮件叠加，有人抱怨。想照着做，一开始就选能管理互斥序列的邮件工具，或者控制免费品数量。2024 年 4 月他开了 Substack「Solopreneur Code」，想靠付费订阅攒一份更稳定的经常性收入。

02｜Swyx 试用一周，把 QA、视频剪辑等五类活交给 Agent

谁·场景
Swyx，Latent Space 播客和 AI Engineer 大会的主理人，同时与 Cognition（Devin 的公司）有关联。
怎么用
用常驻的 Devin Bots 认领整块结果而不是单个任务，由它管理子 Agent、自查，并用交互式页面汇报进度，代替长对话；内容发布流水线主要交给 GPT-6.2 Astra。
结果
他说一周内交出五类工作，同时从本地 worktree 转到云端运行；他还说没有 Astra，公司达不到人均超过 100 万美元的收入效率。
你可以试
挑一个你负责的问题域（比如某产品的回归测试），写清楚「什么算完成」和汇报格式，让 Agent 对结果负责一周，再看你还要介入多少。
注意
同一个模型评价两极：Matt Shumer 测了几周，说 Astra「基本不可用」，他的其他 Agent 退回了大量 Astra 子任务产出；也有人认为问题出在运行框架上。

Swyx 在 X 帖子里说，他试用 Devin Bots 一周，交出了 AEO、QA、跨平台 App 移植、个人事务自动化和视频剪辑。他的结论是：别期待「AI 员工」，我们还没有 AGI，期望过高只会失败。他觉得眼下该要的，是比单个任务高一层的东西：能对结果负责的 Agent 管理者。他说用人也按这个标准：能认领一块问题、主动带着方案回来的人，他更看重。

另一条帖子里，他说新发布的 GPT-6.2 Astra 是他用过最好的流程自动化模型，不再陷入死循环，能通过压缩上下文和写技能来学习，现在跑着 Latent Space 和 AI Engineer 的大部分内容发布流程。

反方意见同样强烈。Latent Space 当日简报整理了评价：Matt Shumer 认为 Astra 基本不可用，Pietro Schirano 认为早期问题多半出在运行框架上。换模型之前，拿自己的真实流程跑一遍再下结论，比看测评可靠。

03｜三个孩子的妈妈，一条提示词做出家庭日程网站

谁·场景
Amanda Caswell，Tom's Guide 作者，在职妈妈，家里三个孩子，日程、晚饭、家务一直靠好几个 App 拼着管。
怎么用
在 ChatGPT Work 里选 Astra，一次写清全部需求：可拖动的周日历、按菜单自动生成并可勾选的购物清单、按家庭成员分配的家务、首页汇总，并要求刷新后数据不丢、不许追问、交付前自测并说明哪些没能验证。
结果
她说成品叫「Hearth」，界面好看，功能都能用，改动会被保存；生成过程比 Gemini Hydrogen 慢，11 分钟时还在测试添加、移动事件和刷新保存。
你可以试
照她的结构写一条提示词，换成自家的人数和需求（假期计划、作业追踪、家庭预算都行），关键是写明「先用示例数据，交付前自测」。
注意
Astra 目前只在 ChatGPT Work 里对部分 Plus、Pro、Enterprise、Edu 用户开放；她展示的是刚做好时的效果，长期使用和多人同步是否顺畅还要自己试。

Amanda Caswell 在 Tom's Guide 记录了这次测试。她故意让几个功能互相依赖：选好的菜要自动进购物清单，家务完成要反映到每个人的周进度，改动要在刷新后还在。她觉得这些不起眼的部分，最能看出模型能不能做出真能用的东西。

提示词里有三句可以直接抄：「用真实感的示例数据，让我马上能测」「每个按钮和计算都必须能用，不要静态稿」「完成前检查并修复问题，告诉我哪些没能验证」。生成过程中模型会汇报进度，她可以随时打断改方向，比如换配色。

这次没有交出任何个人账户或真实数据，用的全是示例数据，风险很低。真要填入家人日程，先弄清数据存在哪里（这类页面通常存在本机浏览器），换设备或清缓存可能丢失。

04｜Simon Willison 把 Agent 执行的代码关进外置沙箱

谁·场景
开发者 Simon Willison，在研究怎样放心地试用本地模型，不怕出错或遭提示词注入后破坏本机。
怎么用
三种实现提供同一个 localhost API（v86 跑 WebAssembly 里的 Alpine Linux、Apple Containers、微软 Quicksand），Pi、Claude Code、Codex 需要执行代码时都调用它。
结果
沙箱自带可选的 HTTP/HTTPS 白名单代理，运行中也能在界面上改；另有凭据替换机制，Agent 能发起带认证的 API 调用，但看不到密钥本身。
你可以试
如果你在本机给编码 Agent 开了执行权限，先把它的执行环境换到其中一个沙箱，只放行项目必需的几个域名。
注意
这是演示模式的参考实现，需要自己配置 Agent 去调用它；Apple Containers 版只适用于 Mac。

Simon Willison 在博客里介绍了和 Prime Radiant 合作的外置沙箱模式。常见做法是把整个 Agent 关进容器，这个模式只隔离代码：Agent 跑在沙箱外，每次要执行代码，就把请求发给沙箱服务。三种实现接口相同，可以随时换底层隔离方式。

有两个设计适合直接借鉴。一是出站白名单：Agent 写的代码只能连你允许的主机，即使被提示词注入，也很难把数据发到别处。二是凭据替换：真实 token 留在代理那一侧，Agent 手里只有占位符，调用 API 时由代理换成真的。

对在工作电脑上跑 Agent 的工程师、对试用来路不明的本地模型的人，这两点都能降低风险。

05｜给地方政府人事部门做软件，客户从 1 家到约 100 家

谁·场景
Brendan Hellweg，曾在巴尔的摩市长办公室工作，参与搭建过 300 人的新冠公共卫生项目，现为 Holly 联合创始人，在 Supercompanies 节目受访。
怎么用
用 AI 在成千上万个各不相同的政府岗位名称之间做数据对标，帮市、县、州的 HR 主管定薪酬、定岗位要求、准备工会合同谈判；这类工作过去要请昂贵的顾问。
结果
他说客户从 1 家增长到约 100 家；针对加州一项新法规的合规计算问题，团队约一周做出方案，再推给加州其他受影响的机构。
你可以试
如果你熟悉某个传统行业的顾问型工作，列出其中「数据量大、规则明确、每家都要做」的环节，这类环节最适合做成软件卖给一整类客户。
注意
政府采购要满足资质和合规要求，节目里他说销售快的前提是机构急需；没有行业经验和人脉的人很难进入。

在 Supercompanies 这期节目里，Brendan Hellweg 说 Holly 最初做的是坑洼上报 App，后来发现政府机构不缺需求，缺的是人手，于是转向人事和薪酬。他认为，在成千上万个岗位名称之间做对标，这种规模只有 AI 能现实地处理。

两个做法可以参考。一是同一个法规问题做一次，卖给所有受影响的机构：加州那个合规方案就是这样推出去的。二是按工资总额的比例看推理开销，不设固定预算，也不用 token 排行榜比谁用得多。他还提到，工程产出加快后，PM 和工程师的配比成了要重新考虑的问题。

原文：Supercompanies (Greg Shove / Section)

今天可以做的一件事

从你手上反复要做的一件事里，挑一件写成一条完整的提示词或任务说明，交给 AI 或 Agent。说明里写清三点：什么算完成；先用示例数据跑通；交付前自己测一遍，并列出哪些没能验证。做完记下总耗时和你改了哪些地方。这份记录用来判断这件事值不值得长期交给 AI，以后也可以整理成第一个免费下载的模板。
