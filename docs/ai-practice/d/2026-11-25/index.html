01｜离开 Kindle 自建 App，一年后月收入近百万美元

谁·场景
Inkitt 创始人兼 CEO Ali Albazaz 在 Sub Club 播客上讲公司起步。旗下有 Galatea、CandyJar 等 App，他说付费订阅用户超过一百万。
怎么用
在免费写作平台 Inkitt 上看读者的行为数据，包括有没有读完、是否熬夜读、分享给多少人，用机器学习挑出好故事，再搬到付费 App Galatea 上卖。增长靠每月约 30 个 A/B 测试，每周约 3000 条新广告素材。
结果
他说，转到 Galatea 的书里约 45% 销售额过 10 万美元，约 16% 过 100 万美元。第一版 App 用三四天做出来，每天投约 20 美元广告验证。
你可以试
如果你的产品还靠别人的平台卖，先算一下复购和流失：平台不给你客户联系方式，复购就很难做起来。
注意
早期他们已经融资两三百万美元，团队十来个人；后来的规模离不开 Kleiner Perkins 领投的 A 轮。

Ali Albazaz 在 Sub Club 节目里说，2017 年前后他们在 Amazon 上卖书，月收入很快到 4 万美元就停住了。原因是流失率等于 100%：客户关系在 Amazon 手里，他们没法把续集卖给同一个读者。于是他们做了自己的 App。第一版只是一组文字截图做成的幻灯片，三四天上线，接上订阅，每天投 20 美元左右的广告，看到有人付了 10 美元。大约一年后，这个 App 月收入接近 100 万美元。

选内容时，他们不看评分和评论，只看行为：读完率、深夜阅读、分享带来的新读者。验证过的故事再逐步加大投入：电子书卖过百万美元，才改编成微短剧。测试微短剧时用了一个 PM、一个工程师、30 天，拍两部，每部约 10 万美元。

能借鉴的是这个顺序：先用最便宜的形式收到钱，再按真实行为数据决定下一笔投入。写作平台冷启动时，他亲自给前 300 位作者发私信，帮他们上传稿子，后来改用征文比赛，他说 Inkitt 没花营销费就到了一百万注册用户。

02｜历史教授交给 AI 一本无名画册，22 分钟查出作者

谁·场景
历史学教授 Mark Humphries，研究对象是耶鲁 Beinecke 图书馆收藏的一本 1808 年匿名速写本。
怎么用
让 GPT-6.2 Astra 自主检索公开的一手和二手资料，提出作者假设，并指出该去查哪份档案来验证。
结果
他说模型用 22 分钟找到一条日记记载：vicomte de Chabot 到访附近河流，日期比画册里的一个日期早五天。模型预测 Chabot 的旅行日记能证实这个假设，后来证实了。
你可以试
手上有卡住的考证或尽调问题，可以让 agent 先列出假设和用来验证的资料，原件由你自己去调阅核对。
注意
关键的那份日记只能向 Cleveland State University 订购，最后一步核实还得靠人去拿到原件。

Simon Willison 转述了这个案例。模型在一份旧档案里找到线索：Chabot 子爵的到访日期，比速写本里提到的一个日期早五天，地点就在附近的河边。模型据此推测，Chabot 的旅行日记能证明画册是他画的。这份日记只能向 Cleveland State University 订购，调来一看，确实证实了。Humphries 说，这份日记本身对加拿大史和毛皮贸易史研究者就是一个重要发现。

这个做法的要点是让 AI 提出可以被验证的预测，而不只是给出一个答案。查资料、做行业研究或竞品尽调的人可以照这个结构提要求：结论、证据链、还缺哪份材料能证实或推翻它。

Humphries 估计，明年春夏历史学界会出现一场「信心危机」，但会比数学界轻：历史学不追求唯一的真理，写作也更接近哲学和文学。

03｜让 Gemini 翻邮箱，几分钟列出全部订阅开销

谁·场景
Lifehacker 作者 Khamosh Pathak，日常全用 Google 的服务，人在印度。
怎么用
打开 Gemini 的 Task 标签，连上 Gmail、Drive 等账户，用 @Gmail 指定数据来源，可以设成每天自动运行。
结果
他说，Gemini 几分钟就列出了订阅清单，统一换算成卢比并算出月均花费，结果输出到 Google Sheets；每日早报提醒了他信用卡快到期的账单。
你可以试
连上 Gmail 后试一句：「找出我所有付费订阅，列出金额和扣款周期，输出到表格。」
注意
退订前必须由本人确认，而且只能整批确认，不能逐个取消勾选；Amazon 等网站会直接拦截 agent。免费版每天只能跑一次，代打电话等功能只在美国开放。

Pathak 在 Lifehacker 的实测里交给 Gemini 的是邮箱权限。他让 Gemini 找出上周的营销邮件并代为退订。每次退订都要他点同意，而且只能整批同意。有一批 10 封里混着两封银行邮件，他就整批跳过了。做完后，Gemini 在 Google Sheets 里生成了一份操作报告。

最实用的是替代付费的订阅管理 App：Gemini 从邮件里汇总出各项付费服务，自动处理美元和卢比两种币种，算出合计和月均。他还用同样的办法统计了当月的咖啡订单。

网页上的任务就弱很多。他让 Gemini 每天盯一款耳机的价格，Amazon 直接把它拦了，印度零售商 Croma 能打开，但判断价格要将近一分钟。免费版每天只能跑一次任务，最多同时 10 个，AI Pro 是 50 个。

04｜Simon Willison：一年三个拐点，能说清的软件就能做出来

谁说的
开发者 Simon Willison，在 AI Engineer Code Summit 做主题演讲，之后写成博客文章。
核心观点
他认为有三个拐点：2025 年 11 月 Opus 4.5 让 Claude Code 默认就能做对；2026 年夏天的 Fable 类模型给目标和工具就会主动想办法；九十月份模型学会了 3D 建模，也开始懂「好玩」。
依据
他让 Opus 5.5「把游戏做得好玩得多」，模型自己试玩了 12 个小时，重新调平衡，他的 RTS 游戏从无聊变得很好玩。
对你的意义
给 agent 派活时，把目标、验收标准和需要的工具都交给它，少去规定具体步骤。
争议·条件
Fable 5.2 是不是新的拐点，他自己还没有定论。独立游戏圈对 AI 辅助编程争议很大，已经吵成了文化战争。

Simon Willison 在这篇文章里说，Opus 4.5 是他用 Claude Code 时第一个「默认结果基本正确」的模型，他从这时起每天用它干活。到了 Fable 类模型，变化在于主动：有一次修 Safari 的显示问题，模型自己写了截图脚本，又起了一个本地日志服务器。还有一次，模型用房间里的五个麦克风，把一个找不到的蜂鸣声定位到约 40 厘米范围内。他的说法是「给目标，给对的工具，然后看它做」。

他对最近几周的判断是：只要你能想清楚并描述清楚一个软件，Fable 就能把它做出来。这是他的个人体验，他也说还在判断这算不算拐点。对读者来说，这意味着瓶颈在往「把需求说清楚」这边移，写需求和做验收的能力会更值钱。

05｜一个周末摸透 Antigravity，最多同时跑了 42 个 agent

谁·场景
做 AI 教程和访谈的 Peter Yang，用一个周末测试 Google Antigravity 搭配 Gemini 4 Neon。
怎么用
用 Orchestrator 和 /swarm 安排多个 agent 分头规划和开发；先跑内置的 /grill-me，让它反过来问澄清问题，把计划补全再动手。
结果
他说最多同时跑过 42 个 agent；他认为 Antigravity 的远程控制比 Claude Code 好用，因为每个线程默认都处于活跃状态。
你可以试
下一个功能动工前，先让 agent 用 /grill-me 这类方式追问你十个问题，再写计划。
注意
多 agent 并行很耗额度和算力，任务拆不开的话，同时跑再多也快不了。

Peter Yang 在 X 帖子里总结了三点。第一，Orchestrator 和 /swarm 适合多个 agent 一起规划和开发，他最多同时开了 42 个。第二，/grill-me 会让 agent 先追问澄清问题，帮你把计划想完整。第三，远程控制比 Claude Code 好用，因为每个线程默认都开着，他在视频里演示了怎么把 Antigravity 加到手机主屏幕。

第二点用任何编程 agent 都能学：动手前先让模型找出需求里的漏洞，比写完再返工省时间。课程视频 17 分钟，已经在用 Antigravity 的人可以直接看多 agent 编排那部分。

今天可以做的一件事

打开 Gemini 或你常用的、能读邮箱的 AI 助手，输入：「找出过去三个月我所有付费订阅和自动续费，列出服务名、金额、扣款周期和最近一次扣款日期，输出成表格。」拿到表后，自己去银行流水里抽查两三项，标出这个月不再用的服务，再亲自去对应网站取消。记下这件事一共花了多久、每月省下多少钱。
