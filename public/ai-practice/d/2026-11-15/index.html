01｜AI 冲垮了教程生意，他的托管产品该卖给谁

谁·场景
Chris Oliver 做 GoRails 教程多年，和一名员工一起经营 Rails 部署工具 Hatchbox。他在 Smart Bear Live 节目上请 WP Engine 创始人 Jason Cohen 和 Tuple 联创 Ben Orenstein 诊断生意。
怎么用
Ben 在节目开录前问自己的编程 Agent：我的副业项目要不要换用 Hatchbox？Agent 算了账，答案是不换。三人随后讨论 AI 时代的小型开发工具该怎么找客户、怎么定价。
结果
Chris 说，AI 冲击教育市场后，Hatchbox 从副业变成主要收入来源，眼下够他一人生活，还没到两人都能靠它生活。半数客户只有一台服务器，最大客户是一家 32 台服务器的代理公司。
你可以试
把你的客户按付费或用量排序，给前三名各写一封邮件，问他们在做什么、替谁做。再问一次常用的 AI 助手，看它会不会推荐你的产品。
注意
Jason 提醒，月付约 20 美元、流失又高的客群很难撑起生意；但转向大客户就要做销售，这对只爱写代码的创始人是真实成本。

Hatchbox 把 Rails 和 Node 应用部署到客户自己的云账户里，起点是 GoRails 最受欢迎的一篇部署教程。Chris 在 Smart Bear Live 上说，他们一直强调比 Heroku 便宜，结果招来的主要是业余开发者。Jason 当场纠正了他的视角：5 台、30 台服务器的客户才是头部，大量业余用户是长尾。他建议 Chris 别再盯着价格，去找那些想用自有基础设施、对价格又不敏感的人，比如替客户做应用的代理公司。这类公司可以把基础设施费用转给客户、自己加价。

Ben 补了一个新问题：以后选工具的可能是 Agent。他的 Agent 比较后认为，自己在 Railway 上每月约 15 到 20 美元，换成 Hatchbox 要付 15 美元，另外还要租 VPS、自己管备份，不划算。他问 LLM 怎么部署业余项目，Hatchbox 也没出现在推荐里。所以靠内容带来客户的老路也要重新检验。

对做小工具的人，可以借鉴两点。一是 Ben 在 Tuple 起步时靠电话拿预付承诺，签下了头 3 万美元。二是 Jason 的说法：策略要贴合创始人本人。喜欢跟技术人员聊技术，就用演示代替幻灯片来卖，但仍要像管项目一样跟进每一单。

02｜强模型做计划，快模型干活，一行配置就能切换

谁·场景
Guillermo Rauch（Vercel CEO）和写 AI 实操教程的 Peter Yang，两人都每天用编程 Agent 做项目。
怎么用
Rauch 在 ~/.fx/AGENTS.md 里写了一行指令：先用最聪明的模型规划，再分派给快速模型的子代理执行。Peter Yang 用 "/doctor prompt-audit" 审查整套 Claude Code 配置，包括 Claude md、skills 和 commands，再用 "/claude-api prompt-audit [skill名]" 深入审查单个 skill。
结果
Rauch 说子代理的效果“非常好”。Peter Yang 说审查命令会给出修改建议，他希望每次新模型发布时 Claude Code 能自动提示运行。
你可以试
如果你在用 Claude Code 或类似工具，今天在 AGENTS.md 里加一行“规划用强模型、执行交给快模型”，同时跑一次配置审查，把建议逐条看过再采纳。
注意
分工的前提是计划写得够细，否则快模型会照着模糊的计划跑偏。审查给出的修改也要人来判断，别一次全收。

Rauch 在 X 上写道，他所有项目都按同一种方式做：最强的模型负责规划，速度快的模型以子代理身份执行。这只是 AGENTS.md 里的一行指令。Peter Yang 在另一条帖子里给了维护配置的办法：新模型发布后，用 /doctor prompt-audit 审查 Claude md、skills 和 commands，让它提出修改。

两件事可以一起用。分工省的是时间和费用，审查保证旧配置跟得上新模型。很多人的提示词和 skill 是为上一代模型写的，换了模型可能写得过细，也可能有些地方已经不适用。适合配置文件积累较多、每天跑 Agent 的工程师和 PM。刚开始用的人可以先只做分工这一步。

03｜做了 46 个 App 后，他砍到 3 个专心做推广

谁·场景
Max 是独立 App 开发者，靠自己的应用辞去了朝九晚五的工作。他在 App Masters 节目里复盘了增长路径。
怎么用
他借助 AI 和 vibe coding 快速开发了大量 App。后来 Apple 政策收紧、商店竞争加剧，他不再继续铺量，集中 3 个 App 测试 ASO、SEO、TikTok、Lemon8 和 Meta 广告。
结果
按节目介绍，他用 6 到 7 个月做到 1 万美元 MRR；聚焦后，这几个 App 的月收入从 2000 美元涨到 8000 美元，约 4 倍。以上都是收入，不是利润，广告投入要另算。
你可以试
如果你手上有几个 App，挑出已经有付费的那一个，用一个月只做推广：改商店关键词、发短视频、小额试投广告，记下每个渠道的下载和付费。
注意
只靠 ASO、发布后就不管的做法越来越难。开发越容易，同类 App 越多，推广渠道要一个个试，花的时间不比开发少。

Max 的经历在 App Masters 节目里讲得很清楚。AI 让做 App 越来越便宜，让 App 长大却越来越难。他一度靠数量取胜，开发了 46 个以上的应用。后来他判断，继续做新 App 解决不了问题，推广才是瓶颈。

他把精力收到 3 个 App 上，同时试自然流量和付费流量：ASO 和 SEO 带来搜索下载，TikTok 和 Lemon8 做内容分发，Meta 广告做付费获客。对用 AI 做 App 的人，这里有一个顺序可以借鉴：先用低成本铺开多个小 App 测需求，找到有付费的几个后，停止铺量，把时间转到分发上。评估效果时，看扣除广告费之后还剩多少收入。

04｜冥想救不了 AI 时代的打工人，独立赚钱的能力才能

谁说的
陈然 2023 年离开大厂，在个人网站发表这篇文章，素材来自他近几个月和硅谷及国内朋友的交流。
核心观点
他依然支持冥想，认为它能帮人保持稳定。但他认为，痛苦的根源是“离开打工就没办法靠自己赚到钱”，应该把找安慰的时间拿去学怎么独立赚钱，并给自己留一两年的耐心。
依据
他引用了三项研究。HBR 一项研究追踪约 200 名美国科技从业者 8 个月，发现 AI 让工作变得更密集。BCG 调研 1488 人，14% 出现“AI 大脑过热”，营销岗达 26%，同时看管超过三个工具后疲劳明显上升。牛津一项覆盖 4.6 万名员工的研究发现，工作条件不变时，企业发冥想 App 测不出效果。
对你的意义
如果你同时开着三四个 Agent 窗口，先减少并行的数量。把 AI 省下的时间拿来做一个平台外的小项目，从解决一个陌生人的小痛点开始。
争议·条件
他自己说转型笨拙了快两年，期间去考过保险、税务、证券的证。全家只靠一份工资和医保的人，要先算清楚能撑多久的过渡期。

陈然的文章写了几类人：同时盯着三四个 Coding Agent、觉得自己像“传话筒”的工程师；伴侣被裁后独自扛房贷和医保的大厂骨干；业余做小网站，几个月没流量就不敢再试的人。他的判断是：这些痛苦都来自同一个原因，就是还没有不靠雇主养活自己的退路。

他的建议分三步：用冥想守住状态，而不是麻痹自己；把上班当成主动选择，用工资和医保换一个过渡窗口；花一两年跑通第一个赚钱闭环。他认为机会在大厂圈子之外，比如考证题库、本地合规指南、传统行业获客线索，一年赚五万到十万美元的小生意并不少见。这些是他的判断，他用来对照的是自己转型的经历和街边的小生意。

05｜一条命令，用本地模型跑起数据库 Agent

谁·场景
开发者 Simon Willison 维护 Datasette，一个开源的数据探索工具，这次更新的是其中配置 LLM 的插件。
怎么用
新版本支持任何兼容 OpenAI 协议的接口。他演示的做法是：下载示例数据库 content.db，用 uvx 加载 datasette-agent，把默认模型指向 LM Studio 的本地地址 localhost:1234/v1，模型选 qwen3.8-27b。
结果
本机会启动一个 Datasette Agent 服务，由本地模型驱动，不需要调用云端 API。Ollama 和 llama.cpp 同样可以接入。
你可以试
装好 LM Studio 或 Ollama 并加载一个模型，照着他文章里的命令先用示例库跑通，再换成自己的 SQLite 文件。
注意
插件还是 alpha 版本。Agent 好不好用，取决于你的机器能跑多大的模型。

Simon Willison 在发布说明里给了完整命令：用 uvx 带上 datasette-agent 启动 Datasette，通过 -s 参数把 datasette-llm 的默认模型设成 LM Studio 上的 qwen 模型，接口地址填本地端口。启动后，就能在浏览器里用本地模型驱动的 Agent 操作数据库。

这对手里有敏感数据、不方便上传到云端的分析师和运营有用。客户名单、内部报表可以导成 SQLite，留在自己电脑上让 Agent 查询和整理。先用他提供的示例库跑通，确认模型能正确理解表结构，再接真实数据。查询结果要和原始数据抽样核对。

原文：Simon Willison

今天可以做的一件事

打开你最常用的 AI 助手，用潜在客户的口吻问它：“我想解决某某问题，该用什么工具或服务？”看你的产品、服务或你所在的公司有没有出现在答案里，再把它推荐的选项和理由记下来。然后从现有客户或同事里挑付费最多、用得最多的一位，发一封短邮件，问他们最近在做什么、还卡在哪里。这两个答案能告诉你：新客户会从哪里来，你该把时间花在哪些人身上。
