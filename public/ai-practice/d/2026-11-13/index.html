01｜装 853 款软件测卸载，又给 400 多位用户补发激活邮件

谁·场景
Tw93 是 Mac 清理工具 Mole 的开发者，开源 CLI 免费，桌面版收费。他在少数派复盘了 1.13 到 1.19 这两个多月的迭代。
怎么用
Agent 借助 computer use 去官网下载软件，安装、检查残留、卸载，过程中还自己写了自动化脚本；用 AI 脚本整理未激活订单；用 Opus 5.5 自绘图标，用 Gemini 改界面文案。
结果
他说第一轮 300 多款软件测完，补了 13 类通用规则、90 多条精确路径，改掉 30 多处不该清理的地方。补发邮件后，他发现不少人填错了邮箱，于是改了购买流程。
你可以试
如果你在卖软件或数字产品，把买了却没用的订单导出来，逐个写一封简短的提醒信，回信可以当作用户访谈来读。
注意
大规模真机测试要有空闲设备和磁盘空间。弹窗、管理员密码这类步骤，仍然需要他在旁边处理。

Tw93 在少数派复盘了 Mole 这两个月的迭代。为了把卸载做干净，他把 300 多款 Mac 软件分成 30 组，让 Agent 用 computer use 逐个下载、安装，检查目录和自启动项，卸载后再找残留，把缺的规则补进 Mole，测试名单后来扩到 853 款。测 30 多款 AI 工具时，他让 AI 对比每次安装前后的状态，把写入的目录记进一份台账。他发现，Mole 支持视障用户时加的无障碍属性，让 AI 能准确找到每个按钮，比靠截图和坐标稳定得多。Windows 版有 482 款软件，跑在虚拟机和一台 24 小时开机的 ThinkPad X1 上测。

他说花时间最多的是一些「不可扩展的蠢事」。他用 AI 写了个本地脚本，列出 5 月到 9 月约 400 单已购未激活的订单，再按月份、国家和语言一封封发信。回信里有人买来送家人，也有人把邮箱写成 gmail.con。他随后改了流程：付款后直接在网页上显示 Key，点击激活还能唤起客户端，自动填好 Key。文案方面，他让 Gemini 输出改前改后的对比和修改原因，再自己一条条审。

他的判断是，代码越来越便宜，差距出在亲手试过才知道的细节上。AI 让一个人也能做完这些原本很耗人力的事，但做不做、做到多细，还是他自己定。

02｜Zotero 导出摘要喂给 AI，一篇综述被《食品科学》录用

谁·场景
少数派作者胡拉图说是食品科学方向的研究生，研究沙棘果渣。这篇综述从选题、找文献、写正文到画机理图，都由他一个人完成。
怎么用
用 Gemini 挖研究空白、生成三级大纲；在 Zotero 用「由所选条目生成报告」批量导出摘要，分批交给 Qwen 分级；按章节生成带出处标注的初稿；用 ChatGPT 出机理图草图，再用 Keynote 重画；最后用 WorkBuddy 检查参考文献格式。
结果
论文被《食品科学》录用并网络首发。他没有说一共省了多少时间，但给出了每个环节的完整提示词。
你可以试
写报告或调研时，先把资料的摘要整理成表格，让 AI 标出相关度和「[需读全文核实]」，再按章节写，不要一次性丢进全文。
注意
他强调这套流程来自工科综述，换到别的领域需要调整。数据、专有名词和方法描述都要人回到原文核对。

作者在少数派拆解了自己的综述写作流程。关键一步是用摘要代替全文：他认为几十篇 PDF 一起丢给 AI，容易超出上下文，也更容易让 AI 编造内容。所以他在 Zotero 里全选文献，生成报告，复制标题、作者和摘要，每次 15 到 20 篇交给 Qwen。AI 输出一张表格，内容包括研究对象、方法、结论和相关度评级，并标出摘要里缺失、要读全文才能确认的条件。提示词里明确禁止 AI 根据标题猜结果。

写正文时，他要求 AI 以研究问题为主线横向对比，不许逐篇复述；每句引用都按「[编号, 第一作者, 年份]」标注出处；摘要支撑不了的论点，就标「[此处缺乏文献支撑，需补充检索]」。初稿出来后，凡是涉及数字、术语和工艺过程的地方，他都回到原文逐一核对。

投稿前，他让本地 Agent 按 GB/T 7714 检查引用顺序和缺失条目，要求它只改副本，先交核验报告，等他确认后再改。这种「先报告、再确认、最后修改」的做法，也可以用在合同、标书这类需要精确核对的文档上。

03｜24 小时做出 Photoshop 近似版，ArtCraft 创始人这样分工

谁说的
Brandon Thomas 是 ArtCraft 创始人兼 CEO，2026 年 11 月在旧金山 AI Engineer Code Summit 上演讲，Latent Space 做了报道。
核心观点
他认为后端、schema 迁移、API 设计应该由人来做；桌面应用、游戏这类「基本不变」的软件，可以放心交给 Agent。他还说，不懂 Rust 也能让 Agent 写 Rust。
依据
他说团队先给模型一份详细提示词，写明 Photoshop 的工具、数据结构和文件导入器，再用一份大提示词让它搭出整个应用，全部兼容 MCP 和 CLI，24 小时内出了近似版。他还说 ArtCraft 已发布 17 款开源应用，每天下载约 170 万次。
对你的意义
给团队分配 AI 任务时，先按「出错后能不能轻易回滚」来分：涉及数据结构和接口的改动留给人，界面和独立工具交给 Agent。
争议·条件
他说功能对齐度刚过 60%；项目 GitHub 上写的功能覆盖约 76%，专业可用度约 46%。他也承认在权限、扩容和 CI 上踩了很多坑，CI 撑不住，只好自建。

据 Latent Space 报道，Brandon Thomas 在 AIE Code 上讲了 ArtCraft 的做法：先复刻用户熟悉的软件，界面和操作手感直接对齐 Adobe，好让画师沿用原来的习惯；之后再做更偏 Agent 的新界面。PhotoCraft 用 Rust 从零写成，他称打开速度是 Photoshop 的十倍。他说开源社区已有约 4000 名开发者，社区还在开发约 300 款应用。他观察到，画师会在他们提供的软件上用 vibe coding 搭自己的工作流。

对读者更有用的是他的分工判断：后端、schema 迁移和 API 设计交给人；桌面应用、游戏以及基本不变的东西交给 Agent，并且放手让它做。这条判断的前提是他们有一个清晰的参照物，也就是现成的 Photoshop 可以对照。没有现成软件可抄的新产品，24 小时能做到什么程度，这场演讲里没有给出答案。

04｜对着手机说话几小时，一个人搭起完整的产品发布

谁·场景
创作者 Riley Brown 在 YouTube 演示用手机完成一次产品发布，这期视频由 Convex 赞助。
怎么用
他在 Claude Projects 里用 Claude Code，混用 Opus 5.5 和 Fable 5.2，靠语音下指令，多个会话同时跑。
结果
他说一共约 20 到 25 条提示词，做出 Screen Studio 的仿制品 Glaze、iPhone 应用、落地页、应用图标，在 Blender 里渲染的 3D 发布视频，以及配 ElevenLabs 配音的 UGC 广告。
你可以试
如果你要发布一个小工具，可以把应用、落地页、图标和宣传视频拆成几个并行会话，逐个在真机上验收。
注意
他演示的是仿制现有产品，方向是明确的。整个流程还要在真实设备上测试，视频里也没有涉及上线后的用户反馈。

Riley Brown 在视频里完整走了一遍：规划和搭建应用，审查落地页设计，在真机上测试桌面版和 iOS 版，设计图标，写发布视频的 brief，用 Blender 渲染 3D 视频，最后生成 UGC 风格的广告。

可以借鉴的是按交付物拆分并行会话：一次发布需要的应用、页面、素材、广告，各开一个会话推进，人负责在真机上验收。想看测试环节，可以从 06:10 开始；想看 3D 视频怎么做，从 17:18 开始。

今天可以做的一件事

打开你的销售后台或表单工具，导出最近三个月「付了钱但没用」或「注册了没登录」的用户名单，可以让 AI 写个小脚本帮你整理。先挑 20 个人，各写一封三四句话的信：提醒他们东西还在，问问卡在哪一步。回信先别急着处理，记下其中出现两次以上的问题，比如填错邮箱、没收到邮件、设备还没到。这些通常就是你购买或开通流程里最先要补的环节。
