01｜AI 转写 1200 小时直播录音，一毛钱漏斗不成立

谁·场景
鸭哥（grapeot）团队研究 B 站中小体量的虚拟歌手和聊天直播间，想弄清打赏的人是谁、在什么时候掏钱。
怎么用
录下 1200 多小时直播音频做语音转写，再和 74 万多条进房记录、礼物账单按时间对齐。用 AI 把谁进房、聊了什么、什么时候付钱串成一条线，还从弹幕闲聊里归纳观众的职业。
结果
按他们的统计，86.6% 的新客花不到 5 元就停了；3.9% 的跳级新客贡献了新客流水的 75.4%，其中八成以上之前已在全站打赏满 3000 元。PK 时段只占 11% 时长，每小时流水 2078 元，约为平时的 14 倍。
你可以试
手上有对话记录（销售通话、社群聊天、直播）又有交易流水的人，可以先挑一小段，把转写文本和订单按时间戳对齐，看看付款前几分钟发生了什么。
注意
样本只覆盖 B 站中小虚拟歌房和聊天房，结论是相关关系，换成大主播或电商直播不一定成立。

鸭哥在《直播观察（三）》里说，他们发现已有研究只抓弹幕和礼物账单，没有录主播的声音，没法把主播说了什么和观众掏钱的时刻对应起来。于是团队自己录了 1200 多小时音频并转写，再和 74 万多条进房记录、51.4 万元实付流水按时间对齐。结论和多数从业者的直觉相反：0.1 元点灯牌的路人几乎不会变成大客户，大额流水靠的是在其他直播间早就习惯付费的老玩家。

这套方法的价值在于把"说了什么"和"付了多少"放到同一条时间线上。他们据此算出几个具体的数：观众刚进房或刚发第一条弹幕时，主播在 45 秒内叫出名字接话，中低消费观众 5 分钟内付钱的概率约是没接话时的 3 倍；观众送礼后主播长时间夸赞，回访率反而从 75.5% 降到 69.6%。决定观众会不会回来的，主要是他当晚自己发了多少条弹幕。

做社群、直播、知识付费或 App 的人可以照这个思路检查自己的转化假设：先确认"低价引流再升级"这条路在你的数据里有没有人真的走通，再决定把精力放在拉新还是留住已有的付费用户。

02｜ChatPRD 免费试用被刷成别人的生产线，创始人决定关停

谁·场景
Claire Vo 经营 ChatPRD，这是一个帮产品经理把想法写成需求文档的 AI 平台，从 GPT-4 时代上线至今，她一直在公开记录开发过程。
怎么用
她在视频里讲了在用量中发现的异常：有团伙循环使用免费试用和优惠码，通过通道接入 ChatPRD 的 Agent，有的只是白用 AI，更多的是转卖 token，或者在上面跑自己的生意。
结果
她举的例子是一家国际化的 Roblox 和 Fortnite 地图工作室，用她的 Agent 做地图，相当于由她出钱养着。高频出现的 prompt 里还有"骑自行车的鹈鹕"SVG，Simon Willison 推测这是用来识别底层模型。她决定全面收掉免费试用。
你可以试
如果你的 AI 产品有免费试用，今天就把试用账号的 token 消耗按账号排一次序，看最高的那一批在做什么，再决定是否给试用设用量上限。
注意
取消免费试用会伤害正常用户的转化，模型成本低、被滥用风险小的产品未必需要这么做。

Simon Willison 在博客里转述了 Claire Vo 的视频。ChatPRD 的免费试用被成批滥用：有人循环使用试用和优惠码，把她的 Agent 接进自己的工作流程。她的原话是："我在资助一家国际化的 Roblox 和 Fortnite 地图工作室。"

有个细节值得做 AI 产品的人留意：滥用者常跑"骑自行车的鹈鹕"SVG 这种 prompt。Simon 认为这是在探测底层模型，因为不同模型家族的输出有明显特征，他自己也用这个方法猜过 OpenRouter 上的匿名模型。也就是说，有人会专门研究你背后接的是哪个模型、值不值得薅。

对 Micro SaaS 来说，免费试用的成本不再只是"送出去几天功能"，每个试用账号都在实打实消耗模型费用。定价和试用设计要把单账号的 token 上限、优惠码能否叠加、异常用量告警一起考虑。Simon 也认为，面对这种程度的滥用，Claire 收掉免费试用看起来是对的决定。

03｜Linear 一半工单由 Agent 创建，AI 功能怎么定价

谁·场景
Cristina Cordova 是 Linear 的 COO，之前在 Stripe 待了七年半。她在 Latent Space 节目里讲了 Linear 年度经常性收入（ARR）过 1 亿美元途中做的取舍。
怎么用
Linear 推出了 MCP server 和 Agent 平台。客服不让 LLM 自己回工单，由 AI 起草、人决定发什么。编码会话让用户自选 OpenAI 或 Anthropic 的模型，按公开 API 价格加少量加价收费。
结果
公司称有 4 万多付费客户，净收入留存 177%。她说三年半来没有一起因为客服体验差引起的投诉升级。客户还常以为回复是 AI 写的，因为回得太快。
你可以试
给自己的产品同时盯两条线：Agent 调用量和用户打开 App 的次数。新的 AI 功能先作为免费 beta 上线，同时提前告知以后会收费。
注意
按 API 原价加价收费的前提是客户愿意自己选模型；按效果收费在 Linear 也还没找到办法。

Latent Space 这期访谈里，Cordova 说 Linear 2025 年 5 月上线 MCP server，现在超过一半的 issue 由 Agent 创建。她的判断是，满足于当"一个挂着 MCP 的数据库"的 SaaS 是在犯大错。她同时看 Agent 用量和 App 用量两条线：Agent 用量涨而 App 用量不涨，说明你正在变成可替换的商品。

定价上，她的原则是对产生成本的部分收费，其余免费。座位费保留；Linear Agent 的聊天功能用的是前沿模型，仍然免费；编码会话和定时任务 Loops 走 AI 额度。新的 AI 功能先作为免费 beta 上线并提前告知会收费，价格从高往低调，不把原来免费的东西改成收费。

她还提醒，现在很多企业有专门的 AI 预算，采购变快了，但买家签的多是一年期合同和付费试点。等这些合同到期续约时，才能看出谁的 ARR 是真的。做小型 SaaS 的人可以照搬两件事：客服用 AI 起草、人工把关；把模型成本透明地传给客户，再加一层服务费。

04｜搭了四套 AI 系统后，他说人只该盯红灯

谁说的
陈然在旧金山工作，过去一年为外部交付门户、外联 CRM、个人常驻代理和多站点内容运营四类真实业务分别搭了 AI 系统，2026 年 11 月在个人网站上写了这篇复盘。
核心观点
他认为 AI 自己不需要看板，看板是给人掌控用的。所以流程分两层：外层是很简单的状态机，只放跨角色交接和确定性门禁；里面交给 Markdown Runbook 处理各种例外。人像塔台一样只看红灯：等自己拍板的、门禁失败或超时的、卡在客户那里的。
依据
依据是他的外联 CRM 实践：把模型调用拆成带提示词版本和 JSON Schema 的任务单，大批量粗活交给本地常开机器上的包月订阅，无风险的结果自动采纳，有异常标记的交给强模型和人复核，几乎不花按次 API 费用。
对你的意义
把手上一个 AI 流程压缩成四到六个阶段，只标出谁交给谁、哪一步要人放行；再把核心查询和写操作逐步封装成 MCP 接口。
争议·条件
这是他个人的判断（2026-11-20），他预计底层运行时 2027 年能到可用水平；本地订阅方案依赖常开机器和订阅额度。

陈然在这篇文章里说，他现在同时维护着四套互不连通的待办表、三套本机执行桥和三套发布保护机制，每次想合并都卡住。他总结出四个痛点：Agent 跑起来就听不见新指令，前台交付和后台协作脱节，云端 API 太贵，几套 SaaS 互相拼接。

可以直接借鉴的是两条原则。一是状态机只管交接点，例外交给 Runbook，避免把业务拆成几十个节点、最后谁也维护不动。二是按变化速度分层：调规则、改提示词、改审批阈值都当作带版本号的数据来更新，正在跑的任务锁定启动时的版本，新任务用新版本，不用重启。

他对 2027 年的判断是：中途转向、耐用租约这类通用的底层管道大概率会有成熟的开源方案，现在自己从零搭性价比很低；但业务口径、多角色可见性和人机授权的红线，没有框架能替你定，现在就该开始整理。

05｜Peter Yang 用五个场景对比 Gemini 4 Neon 和 Opus

谁·场景
Peter Yang 做面向忙碌人群的 AI 教程，Opus 5.5 是他日常工作最常用的模型。
怎么用
他拍了一段视频，用五个使用场景并排测试 Gemini 4 Neon 和 Opus 5.5。
结果
他的结论是，Gemini 4 的三个模型里自己 99% 的任务会用 Neon，它比 Carbon 快很多，效果差不多。他认为每月 100 美元的 Gemini Ultra 很划算，里面还包括 YouTube Premium 家庭版和 20 TB 存储。
你可以试
挑三到五个你每周都会做的真实任务，同一个提示词分别交给两个模型，按速度和需要修改的程度打分，再决定把哪类任务交给哪个模型。
注意
结论来自他的个人测试；Ultra 划不划算，取决于你本来用不用这些捆绑服务。

Peter Yang 在 X 上分享了测试结论：做 3D 和设计，Opus 5.5 仍然更好；写作和语气，Gemini 4 Neon 持平或更好。他还说，Gemini 4 虽然有三个模型，实际上他几乎只会用 Neon，因为它快得多。

这里可以学的是用自己的任务做对比，不看榜单。新模型口碑很好的时候，拿五个日常场景并排跑一遍，比读评测更快知道它在你的工作里能顶替谁。订阅选择也一样：把捆绑服务算进去，看哪个订阅能顶掉你已经在付的钱。

今天可以做的一件事

找一份你手上同时有"对话"和"结果"的数据：销售通话录音和成交记录、社群聊天和下单时间，或者客服工单和退款记录。先只取一周的量，让 AI 转写、整理成带时间戳的文本，再和结果数据按时间对齐。然后问一个具体问题：付款或流失前 5 分钟里，通常发生了什么？如果答案和你原来的假设不一样，你就有了下一次实验的方向。
