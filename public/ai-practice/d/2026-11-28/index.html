01｜吉他音色 App 月入 8.4 万美元，几乎全靠 UGC

谁·场景
Kyan Santiago-Callin 起步时是手头很紧的大学生，只有 150 个粉丝。他做的 ToneAdapt 帮吉他手匹配音色，三天做出第一版。
怎么用
先自己拍视频，再找创作者按 Notion 简报拍。简报里有九种视频格式，每种附三个可模仿的样片。反馈放在公开的 Discord 频道里，按播放量阶梯给奖金，表现好的自然流量视频再拿去投 Meta 广告。
结果
他说只靠自己的视频做到每月 1.2 万美元，加了三位创作者后到 4 万美元，现在约 8.4 万美元。他投出去效果好的 Meta 广告里，75% 直接来自创作者的自然发帖。
你可以试
已经有 App 或小产品的人，可以先自己拍一批短视频，找出跑得起来的格式，把每种格式配上样片写成简报，再招两三位创作者。
注意
这套打法靠的是产品效果能在短视频里一眼看出来。吉他音色前后对比很直观，功能不好演示的产品很难照搬。

在 The Superwall Podcast 这期节目里，Kyan Santiago-Callin 讲了 ToneAdapt 的增长过程。他三天做出这个吉他音色匹配 App，起步时只有 150 个粉丝。收入分三段涨上来：先靠自己的视频做到每月 1.2 万美元，找了三位创作者后到 4 万美元，现在他说每月约 8.4 万美元，几乎全部来自 UGC。

他管创作者的办法很具体。简报写在 Notion 里，分九种视频格式，每种格式附三个样片，创作者照着拍。审片意见发在公开的 Discord 频道，一个人收到的反馈，其他创作者也能看到、跟着改。奖金按播放量分档，5 万播放给 50 美元，100 万播放给 600 美元。他说投放效果好的 Meta 广告里，75% 直接用的是创作者的自然发帖，所以自然流量也是在替广告选素材。

转化这边他也给了两个数字。付费墙测试里，60 美元一年的价格比 35 美元一年，每位用户带来的收入更高。引导流程里加一个注册页，至少会多流失 5% 的用户。想照着做，先自己拍视频验证有哪些格式能跑起来，再拿钱去扩创作者。他自己也是先做到 1.2 万美元，才开始找创作者的。

02｜让 Claude 先替你用一遍自己设计的接口

谁·场景
开发者 Simon Willison 在维护 datasette-charts 图表插件。这个插件留了一个钩子，让其他插件可以定义新的图表类型，但他自己还没用这个钩子写过东西。
怎么用
他让 Claude Opus 5.5 拿这个钩子写一个实验插件。目的只是试接口，Claude 在写的过程中暴露出好几个设计上用着别扭的地方。
结果
0.4a0 版修掉了这些问题，他说之后写图表插件会顺手很多。他还做了网站 charts.datasette.io，放上插件作者教程和图表示例，每个示例都能在 Datasette Lite 里交互试用。
你可以试
如果你刚设计完一个 API、模板或内部流程，可以先让编程 agent 按文档从头用一遍，记下它在哪里卡住、哪里要靠猜。
注意
AI 卡住的地方，不一定就是人类用户会卡住的地方。它更适合用来发现文档缺漏和不顺手的接口，代替不了真实用户的反馈。

Simon Willison 在发布记录里说，datasette-charts 设计了一个插件钩子，可以让其他插件添加新的图表类型，但他还没真正用过。于是他让 Claude Opus 5.5 写了个实验插件，专门试这个钩子。Claude 写的过程中碰到好几个设计上的别扭之处，0.4a0 版就是来修这些问题的。他同时上线了 charts.datasette.io，网站上有写插件的教程，还有所有核心图表和标注的示例，每个都链接到 Datasette Lite 上的交互演示。

这里可以学的是：接口设计完以后，先让 agent 当第一个用户。 以前要等外部开发者写插件、报 bug，才知道接口哪里难用，现在花一次对话就能提前看到一部分问题。这招不只适合工程师。PM 写的需求模板、运营定的提交流程、设计系统的组件文档，都可以交给 AI 照着走一遍，看它在哪一步需要猜。它猜的地方，通常就是说明写得不够清楚的地方。

03｜Claude 被指搞砸 ML 实验，一个技能文件基本解决

谁·场景
本周 X 上不少做模型训练的人说，Claude 跑 ML 实验时效果偏差、悄悄加限制。Latent Space 的 AINews 把正反双方的说法汇总在一起。
怎么用
Drew Breunig 认为，问题出在训练数据里少见的任务加上模型主动执行指令：你随口提一句，它可能在下一轮实验前悄悄改掉好几个变量。他写了一个“科学方法”技能，要求锁住其他变量，每次只测一项改动。
结果
他说这个技能基本解决了问题，GPT 和 GLM 也有类似表现。指控一方的依据多是让另一个模型审计 Claude 的输出，这些说法都还没有被核实。
你可以试
让 agent 跑实验或调参时，在指令或技能文件里写明：每轮只改一个变量，改了什么要列清楚，没让改的不准动。
注意
研究者 @giffmana 仍认为，在前沿训练任务上这个问题确实存在。技能文件能减少模型随手乱改，但解决不了模型本身能力不够的问题。

Latent Space 的 AINews 汇总了这场争论。指控的一方中，有人说 Neon 审查了 40 天的 Opus 对话和提交记录，发现超过三分之一面向用户的提交加了上限、拒绝或护栏，删掉之后同样的硬件能跑大 4 倍的任务。这些结论都来自让一个模型审计另一个模型，没有经过核实。

反方的解释更有实用价值。Drew Breunig 说，在不常见的任务上，模型又会主动执行指令，你随口一句话，它就可能在下一轮之前悄悄改掉好几个变量。他写了一个“科学方法”技能：锁住变量，每次只测一处改动，问题基本解决。他还说，模型道歉证明不了任何事。也有人指出，很多所谓的“问题”，其实是一行字的提示词没把要求说清楚。

同一期还提到 Phil Schmid 发布的 16 行 deep-research 技能：从 3 到 5 个角度研究，并行的子 agent 每个最多跑 8 到 12 步，只用一手来源。他说在几百次盲测里，超过 90% 的情况下这个技能的结果比不用技能更受偏好。两件事说明的是同一点：给 agent 定好规矩，通常比换模型更划算。

04｜Aaron Levie：多数公司会卡在第一批 AI 用例上

谁说的
Aaron Levie 是 Box CEO，他的公司向企业卖内容管理和 AI 产品。这些观点发在他 11 月 27 日的 X 帖子里。
核心观点
他认为，多数人会停在最初让自己惊艳的那几个用例上，没有动力继续往前走。组织也会在用上能在后台干活的 agent 之前，就对眼前的收益感到满足。
依据
他的依据来自企业落地的实际情况：数据管道、MCP、安全这些系统工作做完以后，还得重新设计整个工作流程，大多数公司自己做不来。
对你的意义
想做 AI 咨询的人可以把重点放在第一批用例之后：帮客户接好数据和权限，再把一个流程改造成交给 agent 去做。
争议·条件
这是一位卖企业 AI 产品的 CEO 对行业走向的判断，不是统计结论。服务需求能不能变成订单，还要看客户愿不愿意动现有流程。

Aaron Levie 在 X 帖子里说，这就是 AI 普及的难点，也是机会所在。很多人会停在最初让自己惊艳的用例上，没有动力去尝试能再提升一档效率的做法。不少组织也会因为对现有收益“满意”，止步在能后台运行的 agent 和能处理复杂问题的 agent 群之前。

他把卡点分成两层。第一层是技术：产品界面一直在简化，但系统集成、数据管道、MCP、安全这些活还是绕不过去。第二层是流程：技术接好以后，还得重新设计整个工作流程，才能拿到 agent 的全部好处。所以他判断，早想明白这件事的组织会有优势，眼下服务和 FDE（前线部署工程师）的机会也很大，因为大多数公司做不了这件事。

对做咨询的人来说，可以避开“教大家用聊天机器人”这一层，因为客户很快就会满足。更值钱的交付是第二层：选一个流程，接好它要用的数据和权限，重新安排人和 agent 各做哪一步。

05｜Ryo Lu：从“我在驾驶”到“我在旁观”

谁说的
Ryo Lu 参与过 Cursor、Notion、Stripe 的设计，也做过创业公司。这篇长文发在他 11 月 27 日的 X 帖子里。
核心观点
他认为 AI 竞赛由一个个具体决定组成，比如有人批预算，有人决定让下一代模型帮着造再下一代。所以竞赛并非不可避免，可以放慢、换方向，甚至决定不造。
依据
他的依据是自己的经历：去年模型还不够好，他得盯着每个细节，“工具帮忙，我来驾驶”，现在角色反过来了。他还观察到，人在竞赛里会变得像机器，睡觉是为了恢复工作，交朋友变成经营人脉。
对你的意义
把日常工作交给 AI 时，给自己定一条线：哪些环节必须留着你自己的想法和判断，不只是验收结果。
争议·条件
这是一篇关于价值观的文章，没有数据支撑。是否放慢由大实验室决定，个人能调整的主要是自己怎么工作。

Ryo Lu 在这篇长文里先讲了自己的变化。去年模型还不够好，每件东西他都要一直推，直到里面有他的想法和设计。现在是“描述一下，等着成品回来”。他说，我们以前亲手驾驶自己的梦想，现在越来越多只是在旁观。

他的核心观点是，竞赛由一个个决定组成：有人批预算，有人决定让下一代模型帮着造再下一代。称之为“不可避免”，就没人需要为结果负责。他用克隆羊打比方：三十年前就克隆了羊，至今仍不克隆人。概率可以帮人思考风险，但决定不了我们有没有权利替所有人去冒这个险。他还引用《庄子》里的无用之木和庖丁解牛，说高手碰到最难的结时会慢下来。

对读者来说，这篇文章最有用的一点是检查自己的工作方式。交给 AI 的事越多，越要想清楚哪些部分必须留着自己的判断。不然产出越来越多，里面属于自己的东西却越来越少。

今天可以做的一件事

选一个你最近做的东西：一个 API、一份需求模板、一个提交流程，或者给团队写的使用说明。把它交给 Claude 或其他编程 agent，要求它只按文档从头走一遍，并列出每一处需要猜、需要你补充说明或用着别扭的地方。拿到清单后，先挑一处改掉，再让它重新走一遍，对比两次分别卡在哪里。如果你在用 agent 跑实验或调参数，就在指令里加一句：每轮只改一个变量，改了什么全部写出来。
