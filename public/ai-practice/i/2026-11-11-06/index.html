OpenAI 工程师开车上班路上，用语音开 PR

OpenAI 开发者体验工程师 Dominik Kundel 说，他常在通勤路上和个人 agent 对话、启动 PR，到办公室再审。

谁说的
OpenAI 的 Dominik Kundel 和 Charlie Guo，在 AI Engineer Code Summit 的 Codex 工作坊上分享，会后接受 Richard MacManus 采访。
核心观点
Guo 把语音当成「控制面」，用来管理多个线程、查进度、开新任务，而不只是听写；Kundel 很多任务先交给个人 agent dot 发起，因为它已经掌握他的上下文。
依据
Kundel 说他的 dot 能访问他的开发机、笔记本和云端环境，所以能接手推进 PR；Guo 列了 dot 的三种用法：安全网、在 Slack 里接活、随处可用。
对你的意义
把审查和发起分开：零碎时间用语音派出几个小任务，回到电脑前集中审查结果。
争议·条件
Guo 承认对 Codex 重度用户来说 dot 用着有点别扭；本地任务转到云端仍让不少人困惑，Kundel 说还在改进。

这场工作坊的核心是工作方式。Kundel 演示改网站时会用语音口述，他说在自己还没想清楚要什么时，这样迭代很快。Guo 的用法更进一步：他不把语音当作某一条工作线的输入方式，而是用声音调度所有线程，查进度、从其他应用取数据、新建任务。

两人的建议都很朴素：把推理强度调低（turn it down），遇到问题让 agent 帮你，别对现在的用法太执着，因为工具一直在变。对普通开发者，可以借鉴的是「通勤时发起、到岗后审查」的节奏。前提是 agent 能访问你的代码环境，PR 要等你审过才合并。
